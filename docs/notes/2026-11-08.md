# 研究笔记：这份工具箱里到底有几套代码

原目录约 650 MB / 430 个文件，其实是**三套互不共享源码**的东西挤在一起。理解这一点，才看得懂仓库里为什么同时有 jQuery 时代的网页版和一套 Python 包。

## ① 网页版（本仓库的 `web-toolbox/`）

根目录的 `index.html` + `index.js`（约 4400 行）+ 一批外挂脚本（`batch_pick` / `share_read` / `column_*` / `pdf-upload` / `linspirer`）。jQuery + Bootstrap 4，靠 `?v=` 查询串破缓存；`?debug=1` 开调试版。

运行方式：

```bash
python -m http.server 8088      # 然后就访问 http://127.0.0.1:8088/index.html
```

`file://` 直开会有跨域问题（pdf.js worker、OSS 上传都会挂）。

## ② 桌面端（不在本仓库）

`中育ToolBox/` 下是 Electron 30.5.1 的产物：`app.asar`（包名 `zhongyu-toolbox-rev`，v0.1.4，Vue 3 + Vite 打包）。仓库里的 `patch_client.ps1` 会解包 asar、把网页版文件塞进 `resources/app`，但对这个 SPA **无效**——它只替换外层 `index.html`，Vue 的入口还是 asar 里那份。

## ③ Python / PowerShell 辅助脚本（部分不在本仓库）

`proxy.py`（5005，图片代理）、`share_server.py`（5115，分享中转）、`patch_client.ps1`、以及早期实验 `api.py` / `core.py`（伪造云笔记上传）。

两个坑：

- **不要直接跑 `core.py`**——模块级就会执行上传，而且传参有 bug；
- 早期的 `api.py` / `core.py` / `upload_oss.py` 以及几个 `.md` 里出现过**硬编码的 JWT**，AES 主密钥常量也散落在多个脚本里。这些文件**都没有进仓库**，如果你在自己那份副本里看到，建议立刻轮换令牌。

## 与仓库的关系

- ① → `web-toolbox/`
- ③ 里与「HTML → PDF → 云笔记」有关的部分 → `pipeline/html2note.js`
- 另有一条独立链路（读题作答 → 渲染 → 校验 → 发布）→ `pipeline/scripts/pipeline.py` + `pipeline/tools/answer-pipeline/`
