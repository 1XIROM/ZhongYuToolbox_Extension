# AGENTS.md — 题目答题流水线

本目录是流水线根目录（含 `input/`、`output/`、`scripts/`）。你是执行者：读题图、写草稿、渲染、自检、发布。
每次会话都会加载本文件，所以只放**必须遵守的硬约束**；完整写作规范见 `../docs/answer-pipeline-prompt-codex.md`。

## 0. 边界

- 工作根目录＝本文件所在目录。所有相对路径以它为准；从别处启动时，命令前加 `cd /d "<本目录>" &&`。
- 只在根目录内读写素材、草稿、输出。不要碰相邻的其它项目目录。
- 你不常驻：素材由外部程序下载好并入了队列，你被调用一次就处理完退出。
  **不要挂哨兵、不要定时轮询、不要等新素材**。
- **无人值守**：中途不要向用户提问、不要等确认。不确定的地方按 §3/§4/§9 就地处理
  （看不清写「该处无法辨认」、超出高中范围就不用该解法），处理完在报告里说明。
  这一条优先于个人偏好里的「不确定就问」。
- 上传由外部程序负责：`output/` 里出现 HTML 就会被它转 PDF 传上去。不要自己碰上传。

## 1. 一次任务的标准流程

```bash
python scripts/pipeline.py status
```

- 待答 0 条 → 直接结束，回一句「队列为空」。
- 有待答 → 逐条处理：

| 步 | 命令 | 判据 |
| --- | --- | --- |
| 1 读图 | 见 §3 | 题目原图优先，整页预览只用来查漏 |
| 2 写稿 | 写到 `.workbuddy/auto/drafts/<label>_答案.md` | 格式见 §4 |
| 3 渲染自检 | `render "<草稿>" --title "<学科 · 主题>" --check` | 无「[lint] 阻断」、每块打 ✓、末行「结果：通过，可以 publish」 |
| 4 发布 | `publish ".workbuddy/auto/staging/<label>_答案横版.html" --md "<草稿>"` | exit 0 |
| 5 标记 | `done "<queue 的 json>" --md "<草稿>" --html "output/<label>_答案横版.html"` | exit 0 |

- 待答 ≥2 条：可以并行读图写稿，但 **publish / done 必须串行**（并发写队列会互相覆盖）。
- 块高超 711px 会提示「需压掉 N 行」，按 §4 压缩后重跑同一条 render 命令。高度是浏览器实测值，**不要截图量**。

## 2. 命令清单

```bash
python scripts/pipeline.py status                       # 看待答
python scripts/pipeline.py render "<md>" --check        # 渲染 + 自检（写 staging）
python scripts/pipeline.py publish "<staging html>" --md "<md>"
python scripts/pipeline.py done "<queue json>" --md "<md>" --html "output/<同名 html>"
python scripts/pipeline.py skip "<queue json>" --reason "…"   # 确认无需作答时
```

- 渲染依赖本机 Chrome 做公式预渲染；报 `ChromeNotFound` 时先看环境是否正常，不要自己换渲染器。
- 素材里的 `00_data.mdb` / `00_lock.mdb` / `00_snapshot.bin` 一律忽略，不要解析、不要联网下载。
- **输出乱码**：脚本按 UTF-8 打印，Windows 控制台默认 GBK。先 `chcp 65001`（cmd）或
  `$env:PYTHONIOENCODING="utf-8"`（PowerShell/Codex），否则会把「阻断」和「通过」看反。

## 3. 读图：原图取题干，screenshot 取要求

- `resources.json` 里 `type=0` 的 jpg/webp 是**题目原图**：字大、无遮挡，用来读准题干与图形条件。
- `00_screenshot.png`、`01_screenshot.png` 等 `type=2` 是**整页预览，用户的额外要求通常写在上面**：
  红笔圈注、页边追问、批改、换格式、画图，以及「为什么不是…」这类追问。
- **两张都要读**：先原图取题干，再逐张 screenshot 找要求。**漏读 screenshot 等于整页作废**——
  原图可能与上一条逐字节相同，差异全在 screenshot 上（实例：121.1「这三个反应是什么类型」、
  126.1「用箭头链解决第六题」、126.2「画键线式」、127.1「分析我的解答过程」，都只写在 screenshot 上）。
- 一条素材可能有多张 screenshot，每张都要看，要求可能写在不同页。
- 原图字小就裁局部放大 3～6 倍再读：

  ```bash
  ffmpeg -y -i "input/<目录>/<原图>" -vf "crop=W:H:X:Y,scale=iw*4:ih*4:flags=lanczos" out.png
  ```

- 数值、小数点、正负号、上下标、坐标刻度、角度、波形折点**必须放大核准**。
- 确实看不清就写「该处无法辨认」，不要编。

## 4. 草稿格式

- 首行 `# 学科 · 主题`；每个题块 `## ` 开头，一题一块、一块一页起排；标题里不要出现 `$`。
- 每块顺序：`**答案**：` / `**解析**` / `**补充理解**` / 末段 `**高中范围**：`。`**补充理解**` 必写（2～4 段），细则见 §9。
- 公式一律行内 `$...$`，禁止 `$$...$$`、`\[ \]`、`\( \)`；中文引号用全角 “ ”。
- 答案行用 `\dfrac`（要醒目），正文行内用 `\frac`——正文用 `\dfrac` 会撑高行距，一页少排三四行。
- 化学式用 `\mathrm{}` 写正体；方程式整条放 `$...$`，沉淀 `\downarrow`、气体 `\uparrow` 要写。
- 超页压缩顺序：① 合并相邻短段落（省段间距，内容不删）→ ② 行内 `\dfrac` 改 `\frac` → ③ 收并列句、删重复辨析。
  **不许**删「补充理解」或「高中范围」腾地方。

## 5. 搜索

允许联网查证，但要按规则用，否则会引入错误：

| 情况 | 做法 |
| --- | --- |
| 纯计算、纯推理、课本内推导 | **不搜**，直接做 |
| 公式记不准、常数不确定（溶解度、标准值、实验数据） | 搜，以教材口径为准；论坛/问答站的数值不用 |
| 题目涉及课外背景（某年成果、某工艺原理） | 搜背景，但**结论仍按高中范围写** |
| 网上有原题 | 可对照，**不照抄**；解法与本题条件不符就丢弃 |
| 搜到的答案与自己的推导冲突 | 以推导为准，差异写进「补充理解」 |

- 搜索结果**不能直接进成品**：成品是打印稿，不写 URL、不写「据某某网站」。
- 只在需要核对时搜，不要为了"看起来更全面"堆资料；报告里说明搜了什么、核对了哪几个值。

## 6. 不允许

- 往 `output/` 直接写文件，或跳过 `--check` 就 publish。
- 编造题干、图形条件、选项；看不清就说看不清。
- 为了让成品通过，去改 `scripts/pipeline.py` 的校验规则。
- 把 `.md` 当交付物，或改 `input/` 里的原始素材。
- 覆盖 `output/` 里已存在的同名成品（`publish` 默认拒绝；除非用户明确要求 `--force`）。
- 对 `input/` 里的素材只 `skip` 不产出 HTML（见 §13）。

## 7. 报告格式

全部处理完，用三五句话说明：每条判读成什么题、结论是什么、几个题块、校验数字（题块数/公式数/报错数）、
有没有略去的残缺题、搜过什么。

## 8. 目录速查

| 路径 | 内容 |
| --- | --- |
| `input/<时间>_<标题>_<id8>/` | 一条云笔记的素材（图片 + `resources.json`） |
| `.workbuddy/auto/queue/*.json` | 待答队列，`status == "pending_answer"` 就是待办 |
| `.workbuddy/auto/drafts/` | 草稿 Markdown |
| `.workbuddy/auto/staging/` | 渲染缓存（未发布） |
| `output/` | 已发布成品；外部程序会自动转 PDF 上传 |

## 9. 解析与补充理解（细则）

- 选择题逐项判，写成「A 项：…，正确。B 项：…，错误。」，不要用「A．」开头——题干带选项时会被误判成选项。
- 先依据后式子：「由动量守恒定律得」「由能量守恒定律得」「由动能定理有」；不写「我们可以先考虑」「不难发现」。
- 矢量题第一个方程之前先定正方向。
- 多步方程编 ①②③，末句「联立①②③式解得」；单步写「代入数据解得」。
- 一题多解并列「方法一」「方法二」，各自独立成段，不重复已知条件。
- `**补充理解**` 2～4 段（必写，这是与教辅答案的区别）：这一步为什么能这么列、关键一步怎么想到的、
  换个条件会怎样、与相邻模型的区别、结果的合理性检验。用陈述句，方程独立成行；
  不许用「易错点」「小结」「注意」当栏目名，不许口语化。
- 末段 `**高中范围**：…` 交代知识边界。

## 10. 公式与符号

- 一律行内 `$...$`；禁止 `$$...$$`、`\[ \]`、`\( \)`；不要用 Unicode 上下标拼公式。
- 化学式、分子式、配离子用 `\mathrm{}` 写正体：$\mathrm{HCHO}$、$\mathrm{C_6H_{12}O_6}$、
  $\mathrm{[Fe(OC_6H_5)_6]^{3-}}$。用普通数学模式会把字母渲染成斜体，化学式不规范。
- 中文引号用全角 “ ”。
- 化学方程式整条放 `$...$`，沉淀 `\downarrow`、气体 `\uparrow` 都要写。
- KaTeX 不支持 `\xrightleftharpoons`；带条件的可逆箭头写
  \underset{\Delta}{\overset{\mathrm{V_2O_5}}{\rightleftharpoons}}。
- **温度、角度不要进公式**：`$87\,^{\circ}\mathrm{C}$` 会让 KaTeX 报
  `Got group of unknown type: 'internal'`，整条公式渲染失败、自检直接判不通过。
  改成纯文本 `87 ℃`、`127 ℃`、`30°`；同位素与上下标仍可用公式（`$^{235}\mathrm{U}$`）。
  口诀：**草稿里出现 `\circ` 就改成文本**。

## 11. 物理题体例（教辅体）

- 题干照抄，选择题末尾保留空括号（　　），小问按原编号 (1)(2)(3)。
- 答案一行给全；实验填空按空依次给。
- 解析严格用「由…定律得」引导，方程独立成行，选择题逐项判「故 A 正确」，末尾「故选 B」。
- 「如图所示」在本管线不能嵌图：必须把图中条件文字化（几何关系、正方向、坐标轴、标注量），
  不能只写「由图可知」。

## 12. 附加要求

- 素材里的附加要求必须照做并单独成块，不能简化成普通答题。常见的有：
  「解释某个选项错在哪」「分析学生的手写过程」「图上有追问，一并回答」
  「批改并给分」「翻译」「整理成对照表」。
- 批改类要**四件齐备**：总分 + 分项分 + 逐行批注 + 错因归类，缺一不可。
  - 评分按题目给分拆分（如 4+5+5=14），每小问单独给分并说明扣在哪一步，不只判结论对错；
  - 逐行批注引用学生原式（如 `$p_2S+mg=p_1S$`），指明错在符号、代入还是单位，不能只说「这一步错了」；
  - 错因按「读题 / 建模 / 计算 / 单位」归类，并给可操作的自检办法（代回验算、按过程分段）。
- 翻译要区分「按字面译」与「按作者本意译」。

## 15. 化学：流程用箭头链，苯环用结构式

- **物质变化过程写成箭头链**：`反应物1 --(条件/试剂)--> 反应物2 --> 反应物3 --> …`，
  中间产物逐个写出，条件标在箭头上下；两种反应物汇入下一步时先并列再引箭头。
  总方程式只用于需要配平的定量计算，不用它表达路径。
- **含苯环的有机物必须画键线式**，不用 `C6H5-` 这类文字简式——邻/间/对的位置关系写不出来。
  做法：RDKit 生成 PNG（`Chem.MolFromSmiles` → `Draw.MolsToGridImage`），草稿里用 `![](相对路径)` 嵌入。
  不含位置信息的分子式（C7H8、C6H6O）仍可用文字。
- 图注用英文：RDKit 默认字体下中文会变方框。
- RDKit 需要单独装（可能不在主解释器里）；装不上就退回文字描述，并在页内注明「结构式无法渲染」。

## 13. 什么时候出 HTML

**`input/` 里读到的每一条素材，`output/` 必须有一份对应 HTML**；不允许只 `skip` 不产出。
一份素材一份 HTML，按读到的东西分三种：

| 读到什么 | 产出 |
| --- | --- |
| 正常题目 | 按 §1 走 render → `--check` → publish，得到答案 HTML |
| 成品回灌（页面已给出答案/解析） | 把页面上的答案与解析**整理成规范横版 HTML**，标题下注明「原答案整理」，不补造内容；再 `skip --reason "成品回灌：…"` 标记队列 |
| 空白页 / 测试页 / 图里没有题干 | 出一页**说明 HTML**：写清看到什么、为什么无法作答；用同一套版式 publish，再 `skip --reason` |

- `skip` 只是队列标记，不是「不产出」的许可：可以先 `skip` 再补 HTML，也可以先 publish 再 `skip`；两条都做才算收尾。
- 说明页也要走 render + `--check`，不得 `--force` 手写 HTML 绕过自检。
- 只是问一道题、不涉及 `input/` 素材：**只在回复里答**，最多渲染到 `staging/` 给预览，不写 `output/`。

## 14. 换环境

- 没有 `scripts/pipeline.py` 时，把命令换成自建等价功能，但保留三件事：渲染只写缓存目录、
  发布前做结构自检（题块数＝标题数、无残留 `$...$`、无脚本与外链）、校验不过就退回改稿。
- 版式、草稿格式、内容要求与工具无关，可原样保留。
